1. The most important thing: a preset records "the entire state"

⚠ Please read this part first

When you click ● Record Changes, the plugin writes down the current state of every node on the canvas, exactly as it is — not just the prompt and the parameters, but also:

  • The image loaded in LoadImage (which one, what file name)
  • The model chosen in the model loaders (Checkpoint, UNET, VAE, CLIP, LoRA…)
  • The inputs of nodes like ControlNet / reference image / mask
  • The value of every slider, the selection of every dropdown, the on/off state of every toggle
  • Whether each node is enabled, skipped (bypassed) or disabled

In other words: switching between presets replaces all of these things, not just the prompt.

What this leads to (a real example)

Suppose you have two presets: Image editing mode and Text-to-image mode.

  1. In "Image editing mode" you loaded 6 images into LoadImage.
  2. You switch to "Text-to-image mode" — that preset only recorded 1 image back when it was made.
  3. The moment you switch, LoadImage's image is changed back to that 1 image, and the 6 you just had are all pushed out.
  4. You switch back to "Image editing mode". If you never clicked ● Record Changes before switching away, it rolls back to the last saved version — which may be a state with only 2 images.

There's also a subtler mechanism at work: nodes in a preset that were never recorded are, by default, entirely bypassed by the "untracked-node policy" (see section 7). So those images may have been lost either because they were overwritten, or because the whole LoadImage node was skipped.

✓ The solution

Exclude from recording the nodes you don't want the preset to touch (next section). Once excluded, they're entirely yours to manage by hand, and neither of the mechanisms above will touch them again.

2. Excluding from recording: keeping certain nodes out of the preset's reach

How to exclude

Method Action
Right-click on the canvas (fastest) Select one or more nodes → right-click → 🚫 排除记录 / Exclude from recording
Exclusion list window Right-click on an empty spot on the canvas → 📋 排除记录清单; or open the plugin's Settings window → "Exclude from recording" → open the list

In the list window, each row is a node, and the button on the left is the switch:

  • ● 记录 lit up = this node takes part in the preset's recording and switching
  • ○ 排除 = this node doesn't take part; click it once to switch it back
  • At the top you can search (by node name / type / index), and tick "only show excluded"
  • "Restore all to recording" clears the whole list in one go

What happens to excluded nodes

BehaviourExcluded nodes
When you click ● Record ChangesNot included in the snapshot, never written down
When switching presetsWidget values, models and images are left completely untouched
Enabled / skipped / disabled stateNot touched
The "untracked-node policy"Exempt — they won't be bypassed
The panel's "To record" detectionNot counted — changing one won't turn the preset yellow
The missing-node red dotNot counted
How far the list reaches

The list is shared by the whole workflow and applies to every preset in that workflow. It's saved together with the workflow, so it still works when you open it on another machine.

Node indices only mean something inside this one workflow, so the list doesn't carry over between workflows — in another project you'll have to set it up again.

What about nodes already recorded in old presets

After excluding, the existing records in old presets are not deleted — they're simply skipped when switching. So if you change your mind, just undo the exclusion and those old records work again immediately.

Which nodes are worth excluding

  • LoadImage / LoadImageMask / all kinds of image-loading nodes — the 6-image example above
  • Model loaders: CheckpointLoaderSimple, UNETLoader, VAELoader, LoraLoader…
  • Anything you switch by hand yourself and don't want a preset to carry away

The preset switch node itself (Preset Switch) never takes part in recording anyway, and doesn't show up in the list.

3. Quick start

  1. Add the node X-WIDE/Preset → PresetSwitch on the canvas.
  2. Set up a whole set of parameters, then click ＋ Add Preset on the panel — it starts a new one from scratch.
  3. Tweak the parameters again, then click ● Record Changes to overwrite the current one.
  4. Use ◀ Prev / ▶ Next, or drag the preset_index slider directly, to switch.
  5. Want another, completely different configuration? Click ＋ Add Preset once more.
The difference between "Add Preset" and "Add Sub-mode"
  • ＋ Add Preset: creates a blank preset; the canvas is left exactly as it is, and you click ● Record Changes once you've adjusted things yourself.
  • ＋ Add Sub-mode: attaches an already recorded sub-mode under the current preset, recording only what differs from the parent.

4. How to read the node panel

The red ! at the end of a rowThat preset recorded nodes that are no longer on the canvas; click it to see the list
The round switch at the bottom-leftThe Compact mode switch — click it to collapse / expand the toolbar

The row of buttons below the panel: ＋ Add Preset, ＋ Add Sub-mode, Record / overwrite (it changes colour with the status, and even breathes), 🗑 Delete, ◀ Prev, ▶ Next, ⚙ Settings.

5. Sub-modes

A sub-mode hangs under a main preset (their indices look like 0.1, 1.2). When you switch to a sub-mode, the plugin first applies its parent preset, then layers the differences the sub-mode itself recorded on top.

It's made for "the same pipeline, only a few parameters change" — the parent preset holds the big picture, the sub-mode holds those few variables.

6. Keyboard shortcuts

Default keyWhat it does
Alt + X Enter / leave Compact mode (collapses the toolbar, leaving only the preset list). You can change it in Settings to "collapse the whole panel".
Alt + Z Moves the preset switch node to under your mouse: wherever the mouse is on the canvas, the node jumps there, gets selected for you, and flashes a gold border to say "here it is". When the mouse isn't over the canvas (say it's over the sidebar), it falls back to "move the view to the node".

Both keys can be changed in the Settings window, or cleared entirely. The Settings window warns you live if a combination conflicts.

7. Untracked-node policy (bypass)

This one is easy to get confused about, but it matters. When you switch to a preset, the canvas may hold nodes that that preset has never recorded (ones you added later, for instance). There are three ways to handle them:

PolicyBehaviour
Bypass (default)Sets those nodes to "skipped" — they don't count when the graph runs
EnableSets them to "enabled"
PreserveDoes nothing at all
If your images mysteriously disappear

The default "bypass" is very likely the reason: if a LoadImage was never recorded by that preset, it gets skipped entirely when you switch to it. Excluding nodes like that from recording avoids it completely.

8. The missing-node red dot

If a node that a preset recorded has been deleted, a red ! appears at the end of that row. Click it to open the list, see exactly which ones are missing, and choose:

  • Copy the list — copies out the names of the missing nodes, handy for going to install the plugins
  • Ignore this record — removes the missing nodes from that preset, and the red dot disappears

If you keep missing that little exclamation mark, you can also right-click the preset switch node — the menu lists the presets with missing nodes.

9. FAQ

"Failed to save workflow draft (保存工作流草稿失败)" keeps popping up on the right

That's ComfyUI's own message, not a popup from this plugin — it means the browser's localStorage is full (the quota is about 5MB). That's where workflow drafts are kept.

This plugin stores the preset data inside the workflow too, so a workflow with many nodes and large parameters can easily hit the ceiling. Since v0.12.17 two things have been done about it:

  • Widget-value pooling — parameter values repeated across several presets are stored only once (measured at more than half saved)
  • Fixed a bug where every 250ms it wrongly decided "the layout is broken" and kept triggering re-layout / auto-save

If you're still seeing this message:

  1. Refresh the page and check that the version number at the bottom-right of the node panel header is the new one
  2. After opening the workflow, press Ctrl + S once to save, so the slimmed-down data is written back
  3. If that doesn't help, clear localStorage for this site: F12 → Application → Local Storage → delete this site

Clicking the buttons on the node does nothing / the UI occasionally stutters

v0.12.17 fixed this. The cause was that the layout self-check's criteria left the title-bar height out of the calculation, so every 250ms it wrongly decided "a widget has been squeezed out of the node" and cleared all widget positions to force a re-layout — and ComfyUI works out "which widget did I click" from exactly those positions, so that instant's click got lost. Upgrading makes it go away.

I placed two preset switch nodes and the second one went completely purple

That's intentional: a workflow may only have one preset switch in use. The second one is automatically disabled (a dark red note is drawn on the node) so two controllers don't fight each other. Select it and press Delete to remove it.

Won't long preset names be too long to display

No. Names that are too long in the panel are truncated with an ellipsis, and you can drag the node's width to whatever you like.

When switching presets, why do some nodes turn purple (get skipped)

See "untracked-node policy" in section 7. If you don't want that behaviour, change it to "Preserve" in Settings, or exclude those nodes from recording.

10. Where the data lives

DataLocation
Presets (which nodes and which parameters were recorded) Inside the workflow file, travelling along with the .json. It's there on another machine, and when you send it to someone else.
The exclusion list Same as above — also inside the workflow file
Shortcuts, zoom range, signature and other settings Local to the browser, shared by all workflows

The plugin doesn't go online, doesn't upload anything, and doesn't depend on any third-party Python package.
